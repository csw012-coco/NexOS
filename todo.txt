process model 완전 통합 / Complete process model integration
- i386 spawn/exec path still uses the i386-specific loader/scheduler path:
  kernel_i386_spawn_command -> i386_load_command -> i386_scheduler_spawn.
  i386 spawn/exec 경로는 아직 i386 전용 loader/scheduler를 직접 탐.
- First cleanup landed: i386 spawn/exec now share inheritable fd cloning rules,
  preserve cwd, refresh tty handle from stdio, and close CLOSE_ON_SPAWN fds across exec/spawn.
  1차 정리 완료: i386 spawn/exec가 상속 가능한 fd clone 규칙을 공유하고,
  cwd 보존, stdio 기반 tty handle 갱신, CLOSE_ON_SPAWN fd 닫기를 수행.
- Second cleanup landed: i386 command planning is split from ELF32 loading.
  The plan layer now validates spawn mode, normalizes relative exec paths through the current cwd,
  parses quoted/backslash arguments, and feeds argv/envp into the ELF32 loader.
  2차 정리 완료: i386 command planning을 ELF32 로딩에서 분리.
  plan 계층이 spawn mode 검증, 현재 cwd 기준 상대 exec path 정규화,
  quote/backslash argv 파싱, argv/envp 전달을 담당.
- Move i386 foreground/background spawn toward the common process_exec/process_spawn_from_user model,
  or split a shared process32 backend that exposes the same process/job/session semantics.
  i386 foreground/background spawn을 공통 process_exec/process_spawn_from_user 모델에 더 가깝게 이동하거나,
  같은 process/job/session 의미론을 제공하는 process32 backend로 분리.
- Replace SYS_FORK=-1 compatibility placeholder with either a documented unsupported status
  or a real i386 fork/clone implementation.
  SYS_FORK=-1 임시 구현을 명확한 unsupported 상태 또는 실제 i386 fork/clone 구현으로 교체.
- Align i386 exec_replace action with x86_64 process_exec_replace behavior:
  argv/envp, cwd, stdio inheritance, fd cleanup, process name, exit/wait semantics.
  i386 exec_replace action을 x86_64의 process_exec_replace 동작과 맞춤:
  argv/envp, cwd, stdio 상속, fd 정리, process name, exit/wait 의미론.
- Keep request/result syscall actions as the ABI boundary for wait/exit/yield/sleep/exec.
  wait/exit/yield/sleep/exec는 request/result syscall action을 ABI 경계로 유지.

driver model
i386은 현재 builtin/stub 성격이 강함
x86_64처럼 driver discover/load/init, PCI 기반 드라이버 로딩, /DRIVERS 처리까지 더 맞춰야 함

VFS/pseudo fs 완성도
/dev, /proc, /event, /ram은 생겼지만 아직 x86_64만큼 풍성하진 않음
devfs node, procfs 세부 정보, event stream, pseudo file write 동작 등

mmap/shm/mq/sem 고도화
syscall surface는 들어갔지만 실제 shared mapping, 권한, lifecycle, cleanup은 더 봐야 함

block/storage backend
FAT32/NXFS/ramdisk는 붙었지만 x86_64급 block query, partition tooling, mount edge case는 더 필요함
fdisk류, raw block read/write, sync/flush, error reporting

gfx/audio/net backend
query/stub/일부 backend는 있음
실제 x86_64처럼 그래픽 명령, audio playback, rtl8139 network path를 명령어 단위로 확인해야 함

interrupt/timer/input 품질
IRQ 카운터는 붙었지만 APIC/SMP 쪽은 없음
키보드/마우스/serial/USB 입력도 x86_64와 완전 동일한 수준은 아님

memory management
paging/pmm/user stack/mmap 기본은 있지만
COW, demand paging, page fault 기반 grow, robust user copy 같은 건 남음

compat/common syscall core 정리 잔여

많은 syscall이 request core로 넘어갔지만, 이름/경계/ABI 정리는 계속 다듬을 여지가 있음
